# 元素与图表规范

## 1. 元素种类 → 原生类型

| IR kind | 原生 type | 形状 | 默认背景色 |
|---|---|---|---|
| `terminator` | `ellipse` | 椭圆（开始/结束） | `#b2f2bb` |
| `process` | `rectangle` | 矩形（处理步骤） | `#a5d8ff` |
| `decision` | `diamond` | 菱形（条件判断） | `#ffd8a8` |
| `uml_class` | `rectangle` | UML 类框 | `#fff2cc` |
| `entity` | `rectangle` + `text` + `line` | ER 表卡片 | `#ffffff` + 表头色带 |
| `text` | `text` | 独立文本 | transparent |
| `note` | `text` | 画布旁注（标准字体） | transparent |

## 2. 流程图规范

- 主流程采用**手绘风格**（`roughness:1`、手绘字体）。
- 开始/结束用椭圆；处理步骤用矩形；条件判断用菱形。
- 分支标签明确（edge.label），流程方向清晰；避免交叉连线和节点重叠。
- 连线两端绑定到形状（orbit 绑定），拖动节点时箭头跟随；连线为直线（不支持折线/拐弯）。
- 正确表达循环、提前返回、try-catch 和异常分支（语义层用 sem_id 规划，引擎负责几何）。

## 3. UML 类图规范

- 类框用 `uml_class`，文本用 `\n---\n` 分隔「类名 / 属性 / 方法」三段，渲染为带两条分隔线的三区类框（类名居中、属性与方法左对齐）。
- 关系用 `edge.rel` 表达：`inherit`（空心三角）、`assoc`（实线箭头）、`depend`（虚线箭头）、`compose`（实心菱形）、`aggregate`（空心菱形）；组合/聚合的菱形在 `src`（整体/拥有）端。
- 统一字体、间距、布局。

## 4. ER 图规范（entity）

记法：**表卡片 + 鸦爪（crow's foot）**，面向数据库设计，不是经典 Chen 概念图。

- 每张表一个 `entity` 节点：`text` 是表名，`fields` 是字段列表。
- 字段项：`name`、`type` 必填；`pk` / `fk` / `unique` 生成 PK/FK/UQ 徽标；
  `default` 追加到类型列（如 `numeric(10,2)`、`= 'pending'`）。
- 卡片结构：圆角外框 → 表头色带 + 表名 → 分隔线 → 字段行（徽标列 / 字段名左对齐 / 类型右对齐）。
- 所有卡片子元素放进同一个 `groupIds`，拖动时整体移动；表名绑定到表头容器。
- 关系边：两个 `entity` 之间默认按 ER 连线；也可用 `cardinality` 显式声明。
  - `cardinality` 形如 `"1:N"`、`"0..1:N"`、`"N:M"`、`"1:1"`，左侧属于 `src`、右侧属于 `dst`。
  - `1` / `0..1` → 端部画竖杠 + 基数文字；`N` / `0..N` / `1..N` → 端部画三叉鸦爪 + 基数文字。
  - 连线是**正交折线**，两端 orbit 绑定到表卡片；同一侧多条边按对端位置分散连接点。
  - `label` 是关系动词（如 `places`），放在折线中段旁。
- 自关联（如 `category.parent_id`）用 `src == dst` 的边，会自动绕到卡片右侧形成回环。
- 实线表之间不需要外键约束也能画连线；`fk` 只是字段徽标，不自动生成关系。

### 4.1 ER 内容与语言规范

| 内容 | 语言 / 形式 | 示例 |
|---|---|---|
| 表名、字段名 | 数据库实际英文标识符，原样保留 | `order_item`、`user_id` |
| 数据类型、约束 | 数据库原始形式，原样保留 | `bigint`、`varchar(255)`、`PK`、`FK`、`UQ` |
| 关系名称（`edge.label`） | 简洁中文动词 / 动宾短语 | 下单、包含、归属、关联、支付、归类 |
| 默认值、枚举值 | 与数据库定义一致，不翻译 | `'pending'`、`'free'`、`'CNY'` |
| 图标题（`title`） | 中文 | 「电商订单数据库 ER 图」 |
| 图例、补充注释（`note`） | 中文（技术标记可保留英文） | 「图例：PK = 主键，FK = 外键」 |
| 分组标题（`text`） | 中文（引擎暂无分组容器） | 「交易域」 |

- 不要把表名/字段名/类型翻译成中文，也不要把中文写进字段名；中英文分字段处理。
- 引擎不自动翻译任何内容，规范由编写 spec 的 Claude 执行。

## 5. 分组 / 域容器（group）

- `group` 用 `members` 列出成员节点的 `sem_id`，渲染为透明底 + 顶部色带 + 虚线边框 + 左上角标题。
- 透明底保证即使 patch 新增的组框 index 落在成员之后，也不会遮挡已有卡片。
- 引擎元素的 semId：背景框 = group 的 `sem_id`，顶部色带 = `{sem_id}::hdr`，标题 = `{sem_id}::title`。
- 组成员在布局时单独成块：含 `entity` 用 ER 布局，其余用流程布局；组块之间按网格铺开。
- 成员元素与背景框进入同一个 Excalidraw 外层 group；实体自身的组为内层，
  `groupIds` 顺序为**内层 → 外层**（与插件实测一致）。
- 自关联节点会尽量排在组内右侧，让回环落在组外。
- `group` 标题按语言规范用中文；成员名等仍用英文标识符。
- 限制：只支持一层，不支持组嵌套；成员只能是形状节点；跨组边不参与组内排序。

```json
{"kind": "group", "text": "交易域", "sem_id": "grp_trade",
 "members": ["order", "order_item", "payment"]}
```

`node.style` 对 group 可覆盖 `backgroundColor`、`strokeColor`、`textColor`、
`strokeWidth`、`strokeStyle`、`roughness`、`roundness`。

## 6. 经典 Chen 概念 ER 图（notation: "chen"）

只表达业务实体、实体之间的业务联系和联系基数，不表达属性或物理实现。

- `entity` → 矩形，内部用 `label`（中文业务实体名）；缺省回退 `text`；名称要求中文；
- `entity.fields` 在 Chen 模式**完全忽略**，不生成任何属性椭圆、字段、类型、PK/FK/UQ、默认值或索引；
- 每条 `edge` → 菱形联系，内部用 `edge.label` 的中文业务动词/短语；**必须有中文 label**，不自动填默认词，也不从外键推断；
- 实体与菱形之间用无箭头直线连接；`cardinality` 的左右值标在对应实体端，支持 `1`、`N`、`M`、`0..1`、`0..N`、`1..N`；未提供时不标注；基数由 spec 显式给出，引擎只校验写法，不推断业务规则；
- `group` 仅在明确需要业务域时使用：组框包住实体矩形和组内联系菱形，同域联系菱形也放进该外层 group；跨域联系菱形独立；
- 只接受 `entity` / `group` / `note` / `text`；`entity` 必须有 `sem_id`，边两端必须是 entity；
- 生成后校验：只允许矩形/菱形/联系连线/文本；出现椭圆、`::attr::` 元素、字段/类型/约束文本会直接报错；联系端点必须正确；基数写法必须可解析；连线交叉会以 `chen-line-crossing` warning 提示，实体/菱形/基数标签的块重叠会以 `chen-element-overlap` warning 提示；
- 暂不支持弱实体、多值/复合属性、关系属性、全/部分参与等扩展记法。

## 7. 画布内旁注（note）

- 旁注用标准、易读字体（非手绘）。
- 与相关元素保持清晰空间关系；主图与旁注用独立布局区域。
- 旁注文本可直接是 Markdown 笔记链接或说明。

## 8. ID 与语义 ID

- 原生元素 `id`：8 位字母数字，由引擎自动分配、保证唯一。
- `sem_id`：语义层稳定 ID，供 spec 的 `edges` 引用；引擎内部维护 sem_id → 原生 id 映射。
- 幂等修改时以 `sem_id` 定位元素，避免重复生成。
